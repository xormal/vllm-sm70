# ЛИНЗА СВЯЗЫВАНИЯ: опись, пары, курс обмена

Рабочая книга по АЛГОРИТМАМ (не по ядрам). Ядро — реализация алгоритма на конкретной машине;
переносится не оно, а ФОРМА алгоритма: что он МАТЕРИАЛИЗУЕТ, что ОТКЛАДЫВАЕТ, во что УПИРАЕТСЯ и что
при этом ПРОСТАИВАЕТ. Файл собран из четырёх независимых перепроверок (алгоритмы модели, алгоритмы
vLLM вне ядер, пара-1 «мелкие ядра в эпилоги», цепочка потребителей) и служит входом для КАЖДОГО
следующего решения.

**Метки происхождения числа обязательны и стоят при каждом.**

| метка | что значит |
|---|---|
| `[трасса]` | CUPTI изнутри CUDA-графа, боевой стек. Единственный источник правды по декоду. |
| `[граф]` | скомпилированный артефакт: FX-граф + вывод inductor реального боевого запуска. |
| `[код]` | прочитано в исходнике исполняемого пути (с номером строки). |
| `[арифм]` | выведено из форм/байтов/FLOP. Не время, пока не сверено с трассой. |
| `[стенд]` | микрозамер отдельного ядра. |
| `[сквозняк]` | сквозной A/B на сервере. |
| `[оценка]` | не измерено ничем; вилка. |

Две рабочие точки, их нельзя смешивать:
**декод** — токен **31.10 мс**, 1448 узлов, контекст 63K, B=1 `[трасса]`; часть A/B снята на контексте
12K (токен **26.11 мс**, 1447 узлов, ядра 26.7428 + зазоры 1.5429 = 28.2857 мс трассы, коэффициент
трасса→стена **0.923**). Абсолютные мс от контекста не зависят (это запуски) — доли зависят.
**префилл** — 250K на 2×V100, стена **204.5 с**.

## 0. Валюты

Курс обмена считается только между РАЗНЫМИ валютами. Валюты этой машины:

| валюта | лимит на V100 | как узнать, что хозяин упёрт именно в неё |
|---|---|---|
| ПОЛОСА (байты) | 870 ГБ/с достижимо (841–847 замерено) | снять работу → время не изменилось, если полоса не была лимитером |
| СЧЁТ (FLOP) | 125 ТФЛОП/с f16, 93–100 достижимо в GEMM | доля от пика |
| ЗАНЯТОСТЬ/ЗАПОЛНЕНИЕ (блоки, варпы) | 80 SM, 64 варп-слота | блоков < 2×SM → волн для усреднения нет |
| БЮДЖЕТ ЗАПУСКОВ | **0.928 мкс/узел** (медиана зазора по ВСЕМ 18 типам ядер, p10=0.896) `[трасса]` | зазоры складываются линейно, перекрытий ноль |
| ЗАДЕРЖКА/СИНХРОНИЗАЦИЯ | 15.62 мкс на событие nccl LL | полезная нагрузка ÷ полосу ≪ длительности |
| СОСТОЯНИЕ (регистры, smem) | 255 регистров ISA, 96 КБ smem | разлив/кадр стека |
| ТОЧНОСТЬ (dNLL) | оракульная плотность 0.86–0.90 `[сквозняк]` | страж уже сказал «нет» вне этого коридора |

Три вещи, которые НЕ являются валютой и подставляли нас чаще всего:
объём (байты ≠ время), ожидание (синк ждёт, но не платит), длительность узла (это работа, а не налог).

## 2. ТАБЛИЦА ПАР (по КУРСУ, не по абсолюту)

Правило чтения: **цена считается в валюте ХОЗЯИНА, выигрыш — в валюте ПОТРЕБИТЕЛЯ**; в мс стены
каждая сторона переводится через СВОЙ лимитер. Курс ≥10 — строить, 3–10 — только если дёшево,
<3 — не трогать.

**Не пары, но соседние по цене рычаги** (для сравнения приоритетов):
W8A16 для qkv_proj = 2:1 по байтам = **0.84 мс = 2.7%** (аргумент про 1.85× — счётный и к упёртой в

состояние GDN fp32→bf16 = 0.09 мс при B=1, но 26% потокенного трафика при B=32.

## 3. ПАРЫ ОБРАТНОГО НАПРАВЛЕНИЯ (байтовый пассажир в счётно-упёртого хозяина)

## 6. НАЙДЕННЫЙ ДЕФЕКТ, БЛОКИРУЮЩИЙ ШАГ 1 (тихий, численный)

`fold_take_slot` (`1Cat-vLLM/csrc/quantization/gptq/q_gemm.cu:1896-1932`) детектирует новый захват по
«видел ли незахватный вызов»:

```c
if (st != cudaStreamCaptureStatusActive) { g_zslab.in_capture = false; return {}; }
if (!g_zslab.in_capture) { g_zslab.in_capture = true; g_zslab.bump = 0; g_zslab.call = 0; }
...
if (g_zslab.call == 0) { cudaMemsetAsync(g_zslab.base, 0, g_zslab.bytes, stream); }
```

В **piecewise**-режиме куски одного forward захватываются подряд, а между ними идёт внимание — gptq
вне захвата не зовётся. Значит для кусков 2..N: `call != 0` → **memset в граф НЕ попадает**, слоты
из плиты выдаются → `atomicAdd` копит поверх прошлого токена → **молча неверные числа**. Откаты
301–425, списанные на «нужен подбор `VLLM_GPTQ_FOLD_MB`», — симптом ЭТОГО; увеличение `FOLD_MB`
делает хуже (больше вызовов получит необнулённую память вместо безопасного отката на `torch::zeros`).
Побуквенный тест не поймал: перед каждым full-захватом идут эагерные прогревы, а префилл идёт по
ветке reconstruct и `fold_take_slot` не зовёт вовсе. Полный декодный граф B=1 — единственная
конфигурация без бага.

**Починка (~2 ч):** различать захваты по `cudaStreamGetCaptureInfo_v2(..., &id, ...)` (id уникален на
захват), а не по «видел незахватный вызов». **Второй дефект тем же местом:** нужный размер плиты =
m × 4.057 МБ, а memset всегда заливает `g_zslab.bytes` целиком — при B>1 придётся ставить `FOLD_MB ≈ 100`,
и тогда при B=1 memset станет 118 мкс = **20% съедено от собственного выигрыша**. Заливать надо `bump`
предыдущего захвата. **Третье:** `torch::from_blob` в обход аллокатора ничем не защищён от
`record_stream`/пулов графа; разные batch size делят одни адреса плиты — спасает только строгая
сериализация реплеев, ассерта нет.

## 7. ПРАВИЛО ДЛЯ КНИГИ

### 7.1 Линза связывания (применять к каждому узлу, всегда в этом порядке)

Для КАЖДОГО алгоритма установить **четыре** вещи (четвёртая добавлена этой сессией):

1. **Во что УПЁРТ** — и это выясняется ЗАМЕРОМ «убрать работу и посмотреть, изменилось ли время», а
   не делением объёма на полосу.
2. **Какой ресурс ПРОСТАИВАЕТ** — в процентах от достижимого (не от паспортного) потолка.
3. **Что МАТЕРИАЛИЗУЕТ** — и КТО это потом перечитывает или пересчитывает.
4. **Есть ли у него ЭПИЛОГ и ПРОЛОГ вообще.** У gptq эпилога нет по устройству (split-k `atomicAdd`),
   у cuBLAS его нет по интерфейсу — но ПРОЛОГ (подготовка входа/аккумулятора) есть у обоих, и весь
   выигрыш P1 живёт именно там. Пассажир не обязан ехать эпилогом.

### 7.2 Приём «пассажир / буфер затрат»

ПАССАЖИР — это когда шаг 1 считает то, что нужно шагу 3 и не нужно ему самому, потому что операнды у
него **уже резидентны**, а шагу 3 их пришлось бы добывать проходом по памяти.
Пассажир **не обязан довозить готовый результат**: он везёт частично посчитанное в СЖАТОМ виде
(буфер затрат), потребитель ДОСЧИТЫВАЕТ. **Размер буфера — свободный параметр:** жмём сильнее —
платим больше на досчёте. Эталоны:
- онлайн-софтмакс: (m, l) на строку вместо всей строки оценок (сжатие S → 2);
- таблица границ ‖k‖: заполняет ЗАПИСЬ KV, потребляет ДЕКОДНОЕ ядро (разные шаги, разные ядра,
  записи величина не нужна);
- частичный top-k в эпилоге головы: 80×32 кандидата вместо 248320 логитов (сжатие ~100).

### 7.3 Способ ПОИСКА: двудольная опись, а не перебор идей

Не «придумать, что бы слить». Построить **две колонки** и соединить их механически:

```
ЛЕВАЯ  (хозяева):     узел -> его СВОБОДНАЯ валюта (простаивающий ресурс, % от достижимого)
ПРАВАЯ (потребители): узел -> его ЛИМИТИРУЮЩАЯ валюта (во что упёрт)
РЕБРО: хозяин со свободным X  x  потребитель, упёртый в X, при условии
       "операнды потребителя уже резидентны у хозяина" И "хозяин стоит РАНЬШЕ по зависимости".
```

Сложность поиска — |узлы| × |валюты| (десятки), а не |идеи| (бесконечность), и полнота проверяема:
если у узла не заполнены обе клетки, опись не готова. Именно так нашлись P3 (nccl LL: 80 простаивающих
SM рядом с 145 узлами rmsnorm) и P5 — оба были в описи и оба были пропущены, потому что классифицированы
как «фиксированная статья расхода», а не как хозяин.

**Перед слиянием всегда спросить про ПАРАЛЛЕЛЬНОСТЬ.** Два ядра на двух потоках не платят друг другу
ничего и не требуют торга валютами. Слияние — более дорогой и более хрупкий инструмент, чем
перекрытие; в декоде перекрытий сейчас РОВНО НОЛЬ на 1447 узлов.

### 7.4 Курс обмена и порог

**СЧИТАТЬ ЦЕНУ ПАССАЖИРА В ВАЛЮТЕ ХОЗЯИНА, А ВЫИГРЫШ — В ВАЛЮТЕ ПОТРЕБИТЕЛЯ**, потом каждую сторону
переводить в мс стены через ЕЁ СОБСТВЕННЫЙ лимитер. Порог постройки — **порядка десяти**: платим 1% в
валюте хозяина, получаем 10% у потребителя.

Дополнения, купленные ошибками:
- **Одна валюта на обеих сторонах → курса НЕТ.** Порог «десять» действует только при разных валютах;
  при одной (внимание слоя L → внимание слоя L+1) считать чистое НЕТТО с доверительным интервалом.
- **Числитель ≈ 0 → курс не «бесконечен», а НЕ ОПРЕДЕЛЁН.** Такой пункт нельзя ставить первым в план:
  сначала измерить числитель.
- **Курс над АЛЬТЕРНАТИВОЙ, а не над нулём.** Если дешёвый вариант даёт 0.44 мс за 5 ч, а пассажир
  0.55 мс за 15 ч, то предельный курс пассажира = 0.11 мс за 10 часов, и строить надо дешёвый.

### 7.5 Восемь проверок перед тем, как поверить в курс (каждая куплена ошибкой)

1. **Эта работа вообще исполняется?** `grep` по боевому пути, `[граф]`, а не семантика eager-torch.
   Три пункта из четырёх отчётов умерли здесь.
2. **Хозяин упёрт в то, что я думаю?** Убрать работу и замерить. Байты ≠ время (скан: 618 ГБ дали
   расчётные 33–41%, A/B дал 0.7%).
3. **Цена — в валюте хозяина?** Счётное отношение (1.85×), приложенное к упёртой в полосу операции, —
   не аргумент.
4. **Потребитель упёрт ровно в тот ресурс, который экономит пассажир?** Иначе экономия не покупает
   времени (l2norm у упёртого в заполнение скана).
5. **Ожидание ≠ цена; длительность ≠ налог.** Синк ждёт, но добавляет только пузырь долива (10 мкс, а
   не 89). Налог узла = 0.928 мкс; всё сверх — реальная работа, которая никуда не денется без хозяина.
6. **Есть ли у хозяина точка врезки?** Эпилог/пролог; split-k `atomicAdd` и промежуточный all-reduce
   убивают эпилог полностью.
7. **Занятость посчитана?** Пассажир на одном блоке в волне 640/80 = 40 отстающих блоков; сплиты
   декода непрерывны, и такт шага = САМЫЙ МЕДЛЕННЫЙ CTA, а не средний.
8. **Рабочая точка допустима?** Если у величины есть страж (dNLL), сначала берётся его вердикт, потом
   считается приз. Оценка в удобной точке (оракул@65%) при допустимой 0.86–0.90 завышает приз в
   ~20 раз.

### 7.6 Дисциплина замера (без неё числа выше не воспроизводятся)

- Пары замеров с чередованием **в ОДНОМ процессе**, медиана из 7+, `nvidia-smi` до и после; порог
  теста НИКОГДА не подгонять под результат.
- Каждое число помечать: `[трасса]` / `[стенд]` / `[сквозняк]` / `[арифм]` / `[оценка]`.
- Вентиль обязан быть **ПОВЕДЕНЧЕСКИМ**: при выключении одно, при включении другое, проверять ОБА.
  Проверка через `/proc/<pid>/environ` у воркеров не годится — spawn-блоб не содержит даже
  `CUDA_VISIBLE_DEVICES`.
- **Первым делом искать бесплатный фальсификатор** — численно неверный режим, снимающий ровно
  измеряемое (`VLLM_GPTQ_ZERO_C=never`). Он даёт ПОТОЛОК целой оси за один прогон и стоит 0 часов.
- Автотюн (W8A16, triton) недетерминирован между загрузками и способен дать ±1.4 мс — больше любого
  измеряемого эффекта.
- Рабочая точка A/B и рабочая точка постановки — разные (12K против 63K): абсолютные мс переносятся,
  проценты нет.
